# completion-review.md — Codex 完成评审（相 3）

对一个状态为 `evidence_ready`、已经执行 `verify` 的任务做独立完成评审，产出 `pass` 或 `fail`。

## 铁律

- 实现者不评审自己；评审使用新的 Codex 上下文，不复用实现对话中的未落盘假设。
- 只标真实问题；覆盖不到的能力明确写“未验证”，不能用“看起来没问题”代替证据。
- 评审只读取当前任务、对应 evidence、变更范围和必要源文件，避免把全项目重新装入上下文。

## 评审输入

- 任务定义：`harness.db` 中当前任务对象；
- 证据：evidence 表中该任务的记录，必须有中文 `summary`，并检查 `cmd`、`exit`、原始 `tests`、`rev`；
- 变更：任务声明范围内的文件和 diff；非 Git 工作区直接读取文件并记录 `rev=N/A`；
- 规则：本文件和 `SKILL.md`，不依赖额外 Skill 或运行时。

## 两趟评审

### 第一趟 — 严重问题

- 数据安全：注入、越权、错误的原子性、绕过校验直写数据。
- 信任边界：用户/模型/网络输入是否完成格式、类型、范围和 allowlist 校验。
- 条件副作用：分支是否漏更新关联状态；日志是否声称执行了实际未执行的动作。
- 错误处理：异常是否被吞掉；部分失败是否留下不一致状态；回滚是否可行。
- 命令安全：变量是否拼接进 shell/PowerShell 命令造成注入或误操作。
- 破坏性影响：是否越过任务授权范围，是否缺少备份、确认或回滚路径。

### 第二趟 — 范围与质量

- **scope drift**：是否恰好实现任务声明的范围，不多做也不少做。
- **安全**：默认拒绝、权限边界、对象引用和敏感信息处理。
- **性能**：循环查询、重复扫描、无索引过滤和不必要的 O(n²)。
- **可维护性**：死代码、魔法数、陈旧注释和重复逻辑。
- **测试**：证据是否覆盖成功、失败和边界路径；`exit` 是否为 0。
- **状态完整性**：新增状态/类型/枚举是否处理了所有消费方。
- **可恢复性**：中断后能否靠落盘状态继续，不依赖聊天历史。

## 抑制项

不要把无害的可读性建议、已在本次 diff 中修复的问题、受输入约束不可能发生的边界或个人风格偏好标成失败。

## 中文契约门禁

独立执行技能自带的 `scripts/check_task_harness_language.py`（绝对路径定位见 `SKILL.md`），不得使用 `--templates`。检查原字段中文、禁止翻译旁挂字段、进度可读；人工确认中文说明准确充分，机器标识原样保留。缺少检查结果、退出非 0 或叙事不合格均不得通过。

## 输出契约

先按下列格式逐条列出真实问题，无问题写 `未发现问题`：

```text
[CRITICAL|范围|安全|性能|可维护性|测试|状态] file:line — 问题一句话 → 建议一句话
```

最后必须只保留这一行契约：

```text
HARNESS_REVIEW: pass|fail | <task-id> | <中文理由>
```

有任一未解决 CRITICAL、实质 scope drift、证据不足、独立性不成立或越界破坏性动作 → `fail`；否则 `pass`。中文契约失败或未检查也必须 `fail`。
