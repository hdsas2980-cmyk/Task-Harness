# spec-review.md — Codex 规格评审（相 1）

对刚起草的 `tasks.json` 做一次独立规格评审。评审对象是计划本身：是否合理、可执行、右尺寸；不评审尚未实现的代码。

## 评审原则

- **DRY**：同一职责不要拆成多个重复任务。
- **右尺寸 diff**：偏好能表达目标的最小改动；地基已坏时，明确记录必要重写。
- **boring by default**：优先项目已有能力、标准库和平台原生能力，新增依赖必须有明确收益。
- **复杂度审计**：每个任务都要回答“在解决真实问题，还是在解决自己制造的问题”。
- **blast radius**：高影响面动作单独隔离，写清目标、权限、备份和回滚。
- **可逆性**：删数据、覆盖文件、生产变更等不可逆动作必须显式标注并有授权。

## 规格校验项

- 依赖图无环：`depends_on` 构成 DAG，不存在循环等待或引用不存在的任务。
- 路径归属清晰：任务声明的文件/目录不互相冲突，必要时拆分边界。
- `verify` 可执行且客观：退出码或明确输出能判定通过，不能只写“看一眼”。
- 粒度合理：一句话能说明一个任务的范围；过大要拆，过碎要合并。
- ponytail 阶梯：伪任务、重复实现、无必要依赖和越界扩张都应删除。
- Codex 可执行性：任务不依赖未声明的外部代理、隐藏会话、不可访问环境或未安装工具。

## 中文契约门禁

独立执行技能自带的 `scripts/check_task_harness_language.py`（绝对路径定位见 `SKILL.md`），不得使用 `--templates`。检查原字段中文、禁止翻译旁挂字段、进度可读；人工确认中文说明准确充分，机器标识原样保留。缺少检查结果、退出非 0 或叙事不合格均不得通过。

## 输出契约

先逐条列出真实问题，格式：

```text
[原则|校验项] task-id 或 spec — 问题一句话 → 建议一句话
```

无问题写 `未发现问题`。最后必须只保留这一行契约：

```text
HARNESS_REVIEW: pass|fail | spec | <中文理由>
```

判定：依赖环/不存在依赖、路径冲突、无法客观验证、实质伪任务、越界扩张或 Codex 不可执行 → `fail`；否则 `pass`。中文契约失败或未检查也必须 `fail`。
