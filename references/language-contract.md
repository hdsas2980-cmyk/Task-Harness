# 中文原字段契约

目标：没有看板，直接读 `.harness/harness.db` snapshot 也能理解任务目标、进度、阻塞、验证和评审。JSON 示例只说明 payload 形状，不是活文件。

## 字段边界

- 顶层 `project`、`description`；任务 `name`、`desc`、`reason`、`next` 必填非空中文说明。`reason` 写当前原因，无阻塞也明确说明；`next` 写当前下一项行动，已完成则说明无需继续或如何交接。
- `bundle` 只用任务对象数组；子任务至少有 `id`、中文 `desc`、验证命令 `verify`。已有 `name`、`reason`、`next` 也必须中文。禁止字符串 ID 数组。
- 可选阶段使用中文 `wave` 或数字 `phase`；阶段只是分组，不推导历史状态。
- 证据 `summary` 必填中文，评审 `reason` 必填中文。保留英文原始测试输出 `tests`，不要伪造或改写成成功。
- `id`、引用、JSON 键、状态/评审枚举、命令、路径、修订标识、哈希、工具名称保持原文。这些不是双语字段。
- 禁止 `_zh` 字段和 `board.i18n.json`；不存在翻译兼容方案。
- 必须存在 `harness.db`。证据/评审可为空。`references/templates/` 中的 JSON 只是转换种子，`--templates` 专用于检查种子，不是运行时回退。

## 执行入口与失败处理

在设计交付、推进状态、执行交付和独立评审时，按 `SKILL.md` 的中文契约门禁执行随技能安装的 `scripts/check_task_harness_language.py`。

正常任务不得传 `--templates`。退出码 0 仅说明最低格式与语言检查通过；1 表示契约不合格，2 表示无法读取/处理。失败不签署 `pass`、不推进状态、不翻译兜底；修复授权范围内的 DB payload 后重检。人工评审还要确认文字不是占位、拼凑汉字或不实结论。

## 示例：证据（仅文档演示，不是已执行记录）

```json
{"id":"ev-01","task":"t-01","summary":"十二项测试全部通过，覆盖正常与失败路径。","cmd":"pytest -q","exit":0,"tests":"12 passed","rev":"abc123","ts":"2026-09-12T10:00:00+08:00"}
```

## 示例：独立评审（仅文档演示）

```json
{"id":"rv-01","task":"t-01","ev":"ev-01","verdict":"pass","reason":"验证记录与变更范围一致，未发现阻断问题。","reviewer_context":"independent-review","ts":"2026-09-12T10:05:00+08:00"}
```

## 进度与轨迹

每次追加使用 `## 时间 | task-id | 执行/评审/派卡` 标题，正文写中文进展、状态、验证/评审结论、下一步。任务 ID 必须精确，不能靠任务名称关联。

命令和原始输出放独立代码围栏；协议 `HARNESS_STATUS`、`PROGRESS`、`EXIT_SIGNAL` 保持原样。围栏外是中文叙事，不用英文结论加一个中文标签代替。

看板轨迹跟随当前选中任务，仅聚合该 ID 的进度段、证据、评审；按实际时间展示，缺时间的记录标明未提供时间。不把当前状态推测成历史状态，不把验证成功认作独立评审通过。状态机阶段条不是完成百分比。
