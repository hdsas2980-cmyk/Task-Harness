# Task-Harness 看板能力清单

本页说明 `codex` 分支当前源码的可用功能，不以函数数量、代码行数或未经测量的性能数字作为能力承诺。启动方式见 [看板说明](README.md)，源文件约束见 [中文原字段契约](../references/language-contract.md)。

## 先确认数据边界

- 看板只读取任务、证据、评审和进度，不修改任务状态，不执行验证命令，不签署评审。
- 中文由技能在原字段中写入。界面文案固定中文，任务描述、证据摘要与评审理由直接展示原文；不提供翻译层、`_zh` 双语字段或 `board.i18n.json` 兼容。
- ID、引用、JSON 键、机器枚举、路径、命令、哈希和原始测试输出保持原文。技术原文不是双语业务说明。
- 服务端和技能复用同一份语言校验器。源文件不合格时显示契约错误位置，不把不合格数据当作正常任务渲染，也不自动修复。
- 状态文件优先从项目 `.harness/` 读取，也可以指定直接保存任务文件的目录。四份核心文件必须存在；空证据/评审不代表已完成执行。

## 当前三个标签页

| 标签页 | 内容 | 交互与边界 |
|---|---|---|
| 任务列表 | 按 `wave` 或 `phase` 分组的任务卡片；未指定阶段归入未分组 | 支持搜索、状态/可推进筛选和排序；选择卡片更新当前任务 |
| 任务轨迹 | 当前任务关联的进度段、证据、评审 | 跟随当前行，无下拉选择；精确按任务 ID 关联，按实际时间排序，缺时间明确标注 |
| 进度日志 | 按技能标题格式拆分的进度记录 | 最近记录优先，支持折叠与原文查看；命令和原始输出保留原文 |

已移除重复的下一步、甘特图标签页；当前也没有独立的依赖图标签页。依赖和可推进信息留在任务列表及当前任务详情，不再另设重复视图。

### 任务卡片与证据评审

卡片底部内嵌状态阶段条与证据/评审按钮。阶段条表达当前状态，**不是估算完成百分比**，也不是过去各阶段已经完成的历史证据。

点击卡片上的按钮打开对应任务的抽屉，无须把鼠标移到全局右上角操作。证据摘要取 `summary`，评审理由取 `reason`；命令、测试输出、修订标识等技术细节折叠显示。当前任务区可查看依赖、当前原因和验证命令；复制命令不等于执行命令。

### 轨迹如何对应技能

进度标题使用 `## 时间 | task-id | 类型`，例如执行、评审、派卡。轨迹仅聚合精确匹配当前任务 ID 的记录，并显示真实来源行号；不会用任务名模糊关联，也不会从当前状态编造历史迁移。

验证证据与独立评审分别展示：存在成功测试记录不等于评审通过，`evidence_ready` 不等于 `passed`。

## 载入、刷新与错误恢复

- 可以指定项目目录、调用本机目录选择器，或从 Codex 会话目录中选择任务来源。会话索引只读。
- 浏览器每两秒请求快照，并按文件内容比较结果决定是否重绘，不是只看文件修改时间。
- 载入和证据评审抽屉支持关闭按钮、遮罩和退出键，并处理焦点。用户主动关闭载入抽屉后，启动流程不会强制重新打开它。
- 契约失败时清空旧任务与快照缓存；源文件恢复合格后，即使内容与出错前相同，也能在轮询中恢复展示。
- 不支持直接双击 HTML 以 `file://` 方式使用；应通过启动脚本访问本机 HTTP 服务。

## 服务端接口

服务绑定本机 `127.0.0.1`。以下是四个 `/api/` 路由，不把静态文件路径或内部函数算成 API 数量。

| 方法与路径 | 用途 | 写入边界 |
|---|---|---|
| `GET /api/snapshot` | 当前来源、文件内容与契约检查结果 | 不写项目任务文件 |
| `GET /api/sessions` | 会话来源列表与建议来源 | 不修改会话记录 |
| `POST /api/source` | 切换当前任务来源并返回快照 | 更新来源选择，不写任务状态 |
| `POST /api/pick-dir` | 调用本机目录选择器 | 返回路径或取消结果，不执行项目操作 |

服务还提供页面、脚本及允许读取的任务文件路径。看板会保存最近来源等自身配置；“只读”指不修改项目任务/证据/评审/进度及会话记录，不是整个进程从不写任何配置文件。

## 运行、发布与验收

运行需要 Python 3.10+ 标准库及浏览器；开发回归另需 pytest 和 Node.js，不是看板运行依赖。

在仓库根目录构建：

```powershell
python -X utf8 scripts/build_board_release.py
```

输出 `board/release/TaskBoard/` 和 `board/release/TaskBoard-windows.zip`，包含服务、静态资源、启动脚本、使用说明及与技能一致的校验器。构建按明确文件清单复制，生成 SHA-256 清单，并逐字节比较目录与 ZIP；未知残留文件会阻断打包。生成物不随源码提交，构建本身不会上传 GitHub Release。

回归入口：

```powershell
python -X utf8 -m pytest tests board/tests -q
node --check board/static/app.js
node board/tests/test_ui.cjs
```

前端测试使用模拟 DOM，不等同于真实浏览器视觉验收。语言检查只确认结构与中文最低条件；数据真实性、语义准确性和完成状态仍需可重放验证及独立评审。当前不承诺未经实测的启动时间、内存上限、完整历史重建或真实任务端到端验收。
